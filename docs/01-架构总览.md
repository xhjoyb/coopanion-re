# 01 · 架构总览

> 目标：`Coopanion-v12.71.apk`（`com.palai.prootsmoke`，versionCode 1271，minSdk 24 / targetSdk 35，137,205,527 B）
> 本文只描述**已由产物证实**的结构与数据流；推断处均标注「推断」。

---

## 1. 它是一个「自带 Linux 运行时的 Android 壳」

这个 APK 的实质不是「一个 Android 应用」，而是：

```
Android App（薄壳：窗口 / 无障碍 / 通知 / 语音 / WebView）
        │  解压 assets/payload.asset → files/rootfs-v8-<vc>-<len>/
        │  exec libproot.so → aarch64 proot rootfs
        ▼
Debian-ish rootfs（含 glibc 2.39 + busybox + Node 22）
        │  /bin/node --experimental-transform-types run-core.mjs
        ▼
Node 进程（Cortico 内核 + Coop 桌面宠业务）
        │  监听 127.0.0.1:17788（控制台） / 7797（桌宠页面）
        ▼
WebView 加载这两个本地页面 ←→ Java 通过 addJavascriptInterface 注入能力
```

所以「壳」本身就是它自己打包的 rootfs：**没有第三方加固、没有 DEX 加密、没有 native 反调试**。
两份 DEX 是完整明文（`classes.dex` 101 个类 / `classes2.dex` 23 个类），业务逻辑的大头在 rootfs 里的 TypeScript。

### 1.1 组件清单（Android 侧）

| 组件 | 类型 | 职责 |
|---|---|---|
| `MainActivity` | Activity | 唯一主界面；解包 rootfs、拉起 proot、看护 Node 进程、加载控制台 WebView、开关桌宠 |
| `RepairActivity` | Activity | 修复/自检入口（rootfs 校验失败或用户手动进入） |
| `PetActivity` | Activity | 桌宠的「全屏 App 形态」：透明 WebView 载 `7797/pet?host=app`，右上「✕ 退出」 |
| `PetWindowService` | Service | 桌宠的「桌面悬浮形态」：双窗口（显示层全屏穿透 + 520×520 触摸层），IME 代理注入 |
| `PetWindow2` | 普通类 | 桌宠「第二只」的悬浮实现：`7797/pet?pet=2`，桥名 `pet2Native` |
| `EyesService` | AccessibilityService | 眼睛：`127.0.0.1:17898`，提供 `screen.jpg` / `ui` / `health` / `open_settings` |
| `SenseBridge` | 普通类（单例） | 感知：`127.0.0.1:17899`，提供 `state` / `notifications` / `health` |
| `NotifListenerService` | NotificationListenerService | 抓通知标题/正文，喂给 `SenseBridge` 环形缓冲 |
| `VoiceBridge` | 普通类 | 语音识别：`SpeechRecognizer` → `window.__petVoiceResult` |
| `PetKeyboardGuard` | 普通类 | 键盘高度守卫：无障碍/Insets 双路测高，回报给页面 |
| `WebRetry` | 普通类 | WebView 加载失败重试（指数退避，`PetWebRetry`） |
| `AppLog` / `CrashApp` | 普通类 | 落盘日志（`/sdcard/Download/coop-diag.txt`）与全局崩溃兜底 |

### 1.2 端口全景（关键拓扑）

| 端口 | 归属 | 提供方 | 消费者 |
|---|---|---|---|
| **17898** | 眼睛 | `EyesService`（Java，无障碍截屏 + UI 树） | Node `vendor/pet/src/eyes.ts` |
| **17899** | 感知 | `SenseBridge`（Java，前台应用/点亮/电量/通知） | Node `eyes.ts` 的 `state()` |
| **17788** | 控制台 | Node `cortico` Web 面板（`seed.ts: CONSOLE_PORT`） | `MainActivity` 的 WebView |
| **7797** | 桌宠页面 | Node `vendor/pet/src/server.ts`（`config.ts: port: 7797`） | `PetWindowService` / `PetActivity` / `PetWindow2` 的 WebView |

TS 侧源码里对这些端口的注释是**原厂自述**，可直接作为协议证据：

```ts
// adds the app's label and whether the screen is on and unlocked.
```

## 2. 启动时序（冷启动一次执行流）

1. **`MainActivity.onCreate`** → 建 UI、拿 `WindowManager`、注册 `WebView`、调 `boot()`。
2. **`doBoot()`**（后台线程）：
   1. 取 `assets/payload.asset` 长度 `L` 与 `versionCode` `V`；
   2. 指纹目录 `files/rootfs-v8-<V>-<L>`，标记 `.ok-v8-<V>-<L>`；
   3. 标记不存在 → `extractTarGz(assets, dir)`（**自写 gzip+tar 解析器**，无第三方库）+ `fixPerms()`；
   4. 5 个关键文件**字节数硬校验**（见 §3），不通过则日志 `[CHK] MISMATCH … 解压有问题，语音会失败`；
   5. 通过 → 写 `.ok` 标记，并清理其它 `rootfs-v8-*` 旧目录。
3. **拉起 proot**（见 §3 命令行），`redirectErrorStream(true)`，逐行读 stdout 写 `coop-run.log`。
4. Node 打印 **`core已启动`** → `coreReady = true` → 起 `MainActivity$17` 线程（据此把 WebView 指向控制台）。
5. `process.waitFor()` 返回后：检查 `home/companion/data/.restart-request`，
   存在则**删文件 + 重启内核**（扩展热装后的自动重启，日志：`[!] 检测到重启请求：扩展已安装，正在重启内核以生效`）。
6. 桌宠由用户开关触发 `startPetWindow()` / `togglePetWindow()`：先 `waitPortOpen(7797)`，
   再 `startService(PetWindowService)` 或 `startActivity(PetActivity)`。

## 3. rootfs 解包与 proot 启动（逐字还原）

### 3.1 指纹与校验

```java
long payloadLen = getAssets().openFd("payload.asset").getLength();
int  vc         = getPackageManager().getPackageInfo(getPackageName(), 0).versionCode;
String dirName  = "rootfs-v8-" + vc + "-" + payloadLen;   // 例：rootfs-v8-1271-137xxxxxx
File   dir      = new File(getFilesDir(), dirName);
File   okFlag   = new File(getFilesDir(), ".ok-v8-" + vc + "-" + payloadLen);
```

关键文件字节数白名单（`doBoot` 内硬编码，用于判定 tar 解包是否完整）：

| 文件 | 期望字节数 |
|---|---|
| `app/coop-stage/node_modules/sherpa-onnx-node/node_modules/sherpa-onnx-linux-arm64/sherpa-onnx.node` | **804112** |
| 同目录 `libonnxruntime.so` | **34606912** |
| 同目录 `libsherpa-onnx-c-api.so` | **4613032** |
| 同目录 `libsherpa-onnx-cxx-api.so` | **281200** |
| `bin/node` | **123024744** |

日志格式：`[CHK] critical files: N/5 OK`，不足 5 个追加 `  <-- !!! 解压有问题，语音会失败`。

### 3.2 proot 命令行

```
<rootfs>/libproot.so -0 -r <rootfs 绝对路径> --link2symlink \
  -b /dev -b /proc -b /sys \
  -b <nativeLibDir>:/hostlib \
  -w /app/coop-stage \
  /bin/sh /app/boot.sh
```

- `boot.sh` 不存在时兜底：`/bin/node --experimental-transform-types run-core.mjs`，日志 `[1b] 未找到 boot.sh，直接用 run-core.mjs 兜底启动 …`。
- `ProcessBuilder(list)`：`redirectErrorStream(true)`、`directory(rootfs)`。

环境变量（`environment().put(...)`，并 `remove("LD_PRELOAD")`）：

```
TMPDIR = TMP = TEMP = PROOT_TMP_DIR = getCacheDir().getAbsolutePath()
PROOT_LOADER    = <nativeLibDir>/libprootloader.so
PROOT_LOADER_32 = <nativeLibDir>/libprootloader32.so
PROOT_NO_SECCOMP = 1
HOME  = /root
LANG  = en_US.UTF-8
TZ    = Asia/Shanghai
CORTICO_SUPERVISED = 1
```

### 3.3 自写 tar.gz 解包器（`MainActivity` 内的私有实现）

方法族：`extractTarGz` / `parseOct` / `skipPad` / `skipExactly` / `copyN` / `readFull` / `cstr`。
即：`GZIPInputStream` 套一个手写 tar 头解析器（512 字节块、`ustar` 校验、八进制长度字段 `parseOct`、按 512 对齐 `skipPad`），
**不依赖 Apache Commons Compress 等任何库**——这也是它能做到 137MB 单文件解包而不炸内存的原因（全程流式 `copyN`）。

## 4. Node 侧（rootfs 内）目录与职责

```
/app/coop-stage/                    # 工作目录（proot -w）
├── run-core.mjs                    # 入口：设 CORTICO_* 环境、carryOverHome()、startCore()
├── app/                            # Coop 业务（TypeScript，未混淆）
│   ├── core/boot.ts                # 组装：Cortico 内核 + 桌宠 world + 眼睛 + 控制台
│   ├── core/companion.ts           # 伙伴定义（bot=cormini，displayName=Coo，language=zh）
│   ├── core/seed.ts                # 种子配置（CONSOLE_PORT = 17788、默认 provider、初始面板）
│   ├── core/guide.ts               # 首次引导
│   └── core/bundled-panels.ts      # 内置面板（前端片段）
├── build/cortico/                  # Cortico v0.1.5 —— 通用 Agent 内核（TS，未混淆）
│   ├── src/core/                   # types / util / 事件 / 记忆
│   ├── src/web/                    # 控制台（server.ts / README.md）
│   ├── src/extensions/             # 扩展装载（dry-mount.ts）
│   └── bots/cormini/               # 内置 bot
├── vendor/coo/                     # 伙伴对话层
├── vendor/cua/                     # 设备操作（点/滑/输入）
└── vendor/pet/                     # 桌面宠（最大子系统）
    ├── src/{config,world,eyes,server,tools,repair-agent,window-host}.ts
    ├── src/runtime/  src/asr/  src/console/
    └── web/                        # 前端：pet-app.js / pet-multi.js / pet-core.js / dress.* …
```

`recovered/` 里这些文件全是 **原样文本**（`--experimental-transform-types` 直接跑 `.ts`，
所以包里没有编译后的 JS，只有原始 TypeScript）——这是「源码还原」最核心的一块，**等价于原厂工程**。

**出厂配置现状**（`recovered/coop-stage/home/companion/config.json`，原样引用）：

```json
{
  "displayName": "Coo",
  "language": "zh",
  "activeProvider": "deepseek",
  "providerSchemaVersion": 3,
  "web": { "port": 17788 }
}
```

`deployment.json` 只有 `{"bot": "cormini"}`。`home/providers/` 下 **9 个 provider**
（`deepseek` / `doubao` / `glm` / `kimi` / `minimax` / `openrouter` / `qianfan` / `qwen` / `stepfun`）
的 `.env` **全部是注释模板**（形如 `# DEEPSEEK_API_KEY=sk-xxx`）——**包内没有任何可用密钥**，
首次使用必须自己填一个。默认模型取 `vendor/coo/README.md` 的 provider 默认表
（`deepseek` → `deepseek-flash`，`openrouter` → `deepseek/deepseek-v4.1-flash`）。

## 5. 三层能力边界（谁负责什么）

| 能力 | 实现层 | 说明 |
|---|---|---|
| 看见屏幕 | `EyesService`（Java） | 无障碍 `takeScreenshot`，Android 11+ 才允许后台截屏；JPEG + UI 文本树 |
| 知道前台应用/通知/电量 | `SenseBridge` + `NotifListenerService`（Java） | `UsageStatsManager` + `NotificationListenerService` |
| 说话/听话 | `VoiceBridge`（Java，系统 `SpeechRecognizer`）+ rootfs 内 sherpa-onnx | 在线识别走系统服务，本地 ASR 走 sherpa-onnx |
| 点屏幕 | `vendor/cua`（Node）+ 无障碍注入 | — |
| 桌宠显形 | `PetWindowService` / `PetWindow2` / `PetActivity` | 三种形态共用 `7797/pet` 页面 |
| 输入法注入 | `PetWindowService$ImeCommitConnection` | 把 IME 上屏内容转发进 WebView |
| 对话与工具 | `build/cortico` + `vendor/coo` | 大模型走用户自配 provider |

## 6. 与「加固」的关系（定案）

| 判定项 | 结论 |
|---|---|
| Manifest 桩 Application | 无（`android:name` 为业务类，非 `com.stub.*` / `com.secneo.*`） |
| 壳 so（libjiagu / libDexHelper / libnesec…） | **不存在** |
| assets 壳数据（ijiami.ajm / 0OO00* / _ntcfg_.data…） | **不存在** |
| DEX 加密 / 方法抽取（nop 方法体） | **不存在**，两个 dex 全明文、方法体完整 |
| VMP / native 保护 | **不存在** |
| 签名校验 | 仅系统默认，无自校验代码 |

唯一「打包技巧」是 `assets/payload.asset`（gzip+tar 的 aarch64 rootfs），
它靠 `MainActivity` 自写的 tar 解析器在首次启动时展开——属于**自解压运行时**，不是加固壳。
因此本样本不需要脱壳、不需要 56.al、不需要 Frida dump；`classes*.dex` 直接反汇编即可。
