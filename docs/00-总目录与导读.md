## 1. 一句话结论

1. **它不是加固壳，是「自带 Linux 运行时的 Android 薄壳」**：Java 侧只有 **124 个类 / 544 个方法**，
   真正业务是 `assets/payload.asset` 里那套 **344.11 MiB 的 aarch64 rootfs**（gzip + tar）。
2. **业务源码是原样的 TypeScript，没有编译、没有混淆**：863 个文件里有 259 个 `.ts`，
   原厂用 `node --experimental-transform-types` 直接跑 `.ts`，所以包里根本没有编译后的 JS。
3. **难点不在对抗，在协议**：桌宠是「两层悬浮窗 + WebView + Node 页面」，Java ↔ JS 有三条桥接通道，
   最巧的一处是用 1×1 隐藏 `EditText` 骗输入法再包装 `InputConnection`。
4. **不需要脱壳、不需要 Frida dump**：两个 dex 全明文、方法体完整、无桩类 / 无壳 so / 无壳 assets / 无 VMP / 无自校验。
5. **包内没有任何可用 API Key**：9 个 provider 的 `.env` 全是注释模板，首次使用必须自己填。

## 6. 「源码还原」到底还原到什么程度（重要，别误读）

交付是**三件套**，性质完全不同：

| 产物 | 位置 | 性质 | 能否直接编译 | 用途 |
|---|---|---|---|---|
| **smali 全量** | `src/java2/classes/`（124 个） | 字节码 1:1 反汇编，**逐字**，含 `# registers=` / 访问标记注释 | 不能（不是 Java） | **唯一权威依据**，有争议查它 |
| **TS/JS 工程** | `src/recovered/`（863 个） | **原样文本，未改动一字**（原厂就没编译） | 能——原厂用 `node --import tsx` 直跑 | 这才是真正的「业务源码」 |
| **Java 重建** | `docs/02` | 人工重建的可读 Java：签名/常量/调用/日志文案逐字来自字节码，结构已还原，分支按语义合并（标注 `// 推断`） | **不能**（缺 `R`、资源、Gradle；方法体是摘要式） | 读逻辑、改逻辑的参考 |

明确说清楚三件事，避免期待错位：

1. **没有做「可编译的 APK 工程」**。要把它编回可安装包，需要补 `R` 资源索引、`AndroidManifest` 引用、
   资源目录、Gradle 配置，并把 124 个类的**方法体全部补成可编译 Java**——成本是现在的数倍，
   而收益接近零（改包只需改 smali 后重打包，不必还原成 Java 工程）。详见 §8「有意不做」。
2. **重构幅度是有边界的**：`lambda` / 匿名类已还原成可读形态（`$15` → `OnReceiveValue` 等），
   但**没有**把 R8 内联打散的代码"美化"成原厂写法；凡是不能由字节码唯一确定的，一律标 `// 推断`。
3. **`recovered/` 里的 TS 不是「反编译产物」**，是原厂原文件。所以 `docs/03` 里的页面侧证据
   （`pet-multi.js:445` 的 `unionString()`、`config.ts: port 7797`）是**直接读源码**，不是猜。

## 9. 术语与记号约定

| 记号 | 含义 |
|---|---|
| `$15` / `$8$1` / `$16$1` | smali 的匿名内部类命名；`$8$1` 是 `PetWindowService$8` 里的第一个匿名类（`Sink` 的实现） |
| `-$$Nest$m…` / `-$$Nest$fget…` | R8 生成的**桥接方法**：内部类访问外部类的私有方法/字段。看到它就是「这里有个匿名类」 |
| `inj_01 … inj_12` | 12 段注入脚本的编号，**编号规则见 `03 §2.1`**（按 `evaluateJavascript` 调用点顺序），与 `src/js/inj_XX.js` 一一对应 |
| `§N` / `§N.M` | 只写「篇 + 小节」，**不写行号**——行号会随修订漂移 |
| `static_values` | DEX 里 `static final` 常量的真实值区（`read_static.py` 取的就是它） |
| 「推断」/「推测」 | 两档不确定度：`推断` = 字节码可唯一确定但写法被内联打散；`推测` = 有证据但未逐行验证 |
| 数字口径 | 一律**字节求和**（`os.path.getsize`），不用 `du`；时间一律实测（`time`） |

## 10. 维护纪律（写给后来者，也是本轮踩过的坑）

1. **字节码 > 文档**。文档与 smali 冲突时**一律以字节码为准**，并改文档 + 在文件头写「修订记录」，
   不允许静默改掉。第一次实例：`docs/02` 的 **修订记录 v2**（16 处回改）。
2. **文档回改必须带唯一匹配断言**。模板是 `src/patch_docs02.py`（`cd docs` 后执行）与
   `src/patch_docs_round2.py`（工程根执行）：每条 `old` 必须在全文**恰好出现 1 次**，
   否则整体中止不写盘。这样改 16 处和改 1 处一样安全。
3. **不要重跑 `patch_decode.py` / `patch_fields.py` / `fix_indent.py`**。它们是「改 `dex2smali.py` 源码」的脚本，
   只对未打补丁的原版幂等；现在仓库里的 `dex2smali.py` 已经是打完补丁的版本。详见 `04 §5.3`。
4. **新增结论必须能一条命令复现**。`04` 附录那张「所有数字的来源」就是为此存在；
   写不进那张表的数字，不要在正文里当事实用。
5. **大文件不要 `cat`**（`payload.asset` 137 MB）；要清单用 `tar -tz`，要子集用成员名前缀过滤
   （busybox tar **不支持** `--wildcards`）。
