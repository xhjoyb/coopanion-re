# 07 · 出包链：从改一行 JS 到装进手机

> 一句话：**`bash tools/repro_pet3.sh` 一条命令复现出 pet3，sha256 逐字节一致**（`38128c2e…d26032`，137,195,102 B，28.6 s）。
> 这条链原先散在 `.operit/` 的四个一次性脚本里、路径写死、克隆仓库造不出来；现已全部收口到 `tools/`。

## §2 三样「不入库」资产

`.gitignore` 排掉了 `*.apk` 与 `.operit/`，所以下面三项必须自备，缺了脚本会直接报错并提示：

| 资产 | 路径（默认） | 怎么来 |
|---|---|---|
| **原厂 APK** | `apk/Coopanion-v12.71.apk` | 137,205,527 B / 29 条目，`md5sum` 核对 `ed319932…e00b1` |
| **签名证书** | `.operit/sign/coop.keystore` | 2,644 B，PKCS12，口令 `123456`，alias `coop`，`CN=Coopanion Rebuild, O=CoopanionRe, C=CN`。**这份只在设备上，丢了就再也装不回 pet3**（只能卸载重装丢数据）。设备上另有两份备份：`/sdcard/Download/rev_tmp/keystore_backup/coop.keystore` 与 `.backup/coop.keystore`，三处 sha256 同为 `951c5675…b617d7` |
| **apksig jar** | `.operit/sign/apksig-2.3.0.jar` | 194,857 B，Maven 取：<br>`https://repo1.maven.org/maven2/com/android/tools/build/apksig/2.3.0/apksig-2.3.0.jar` |

签名命令实际是（`apk_build.py` 内部就是这么调的，参数三件套换成你的即可）：

```bash
java --add-exports java.base/sun.security.x509=ALL-UNNAMED \
     --add-exports java.base/sun.security.pkcs=ALL-UNNAMED \
     --add-exports java.base/sun.security.util=ALL-UNNAMED \
     -cp .operit/sign/apksig-2.3.0.jar tools/java/Sign2.java \
     <in.apk> <keystore> <pass> <alias> <out.apk>
```

## §4 出包步骤（日常改 JS）

```bash
python3 tools/apk_build.py \
  --patch-tar './app/coop-stage/vendor/pet/web/pet-core.js=src/recovered/vendor/pet/web/pet-core.js' \
  --patch-tar './app/coop-stage/vendor/pet/web/pet-app.js=src/recovered/vendor/pet/web/pet-app.js' \
  --dex 'classes.dex=src/dex-baseline/classes.dex' \
  --dex 'classes2.dex=src/dex-baseline/classes2.dex' \
  --out .operit/work/pet4_unsigned.apk \
  --keystore .operit/sign/coop.keystore --ks-pass 123456 --ks-alias coop \
  --signed-out .operit/repack/Coopanion_v12.71_pet4_signed.apk

python3 tools/apk_verify.py --apk .operit/repack/Coopanion_v12.71_pet4_signed.apk \
  --contains './app/coop-stage/vendor/pet/web/pet-core.js=palette: icon('
```

| 参数 | 语义 |
|---|---|
| `--base` | 起始 APK，默认 `apk/Coopanion-v12.71.apk`；payload 从它的 `assets/payload.asset` 读起 |
| `--patch-tar NAME=FILE` | 替换 payload tar 内条目（可多次）；名字不带前导 `./` 也行 |
| `--payload-tgz FILE` | 直接用现成 `payload.tar.gz` 跳过 tar 替换；**与 `--patch-tar` 互斥** |
| `--dex NAME=FILE` | 替换包内 dex（可多次），会校验 `dex\n` 魔数 |
| `--signed-out` | 给了就签名 + 自动验签；需要 `--keystore/--ks-pass/--ks-alias` |
| `--work` | 中间产物目录，默认 `.operit/work`（payload 重压的 tar.gz 落这里） |

**关键实现细节（改动前必读）**

1. **tar 替换**：按 ustar 头逐块拷，命中目标才改 size 字段并重算 `chksum`（第 148..156 置空格求和 → `%06o` + `\0 `）；`LongLink`(typeflag `L`) 的 real name 跟随后处理；遇全零块即 EOF，其后字节原样透传。
2. **gzip**：`GzipFile(filename='', compresslevel=6, mtime=0)` → 头恒为 `1f 8b 08 00 00 00 00 00 00 ff`。改压缩级别或不去掉 filename/mtime 都会让产物 sha256 全变。
3. **zip 对齐**：`STORED` 条目按 `lib/`→4096、其余→4 补 extra field（`align_extra`，`0 < pad < 4` 时再加一个 align——这条怪规则必须照抄，它是原脚本的实测行为）；`DEFLATE` 条目（`assets/payload.asset`）不管对齐，所以 `doff % 4 = 2` 属正常。跳过 `META-INF/{COOPANIO.SF,RSA,DSA,MANIFEST.MF}` 与 `META-INF/version-control-info.textproto`（重签会重建）。
4. **dex**：不传 `--dex` 得到的是「原厂 dex + JS 补丁」变体，**不等于 pet3**，见下节。

## §5 ⚠️ pet3 的 dex 与原包不同（重要事实）

之前 `BASELINE.md` P8 写的「pet3 只动了两个 JS、不改 dex」**是错的**。实测：

| 条目 | 原包 | pet3 | 差 |
|---|---:|---:|---:|
| `classes.dex` | 98,744 B / `45b2e89e…` | 98,808 B / `ffd82303…` | +64 |
| `classes2.dex` | 37,212 B / `cab5aed2…` | 37,308 B / `c1504c10…` | +96 |
| `assets/payload.asset` | 137,118,068 B / `39899fa0…` | 137,118,218 B / `e1ce7ad8…` | +150 |

来源：那条「反编译重建 Java 工程」线（34 轮 CI，运行时已判不可用）留下的 smali 往返产物 `.operit/sm/out1.dex` / `out2.dex`，
在 repack 时被一并打进包。**但这条 dex 链在真机上确实跑得起来**（pet3 覆盖安装并验证过），所以基线事实保留，
只是从此刻起必须如实记录：**要复现 pet3 就得带上它**。

两份 dex 已入库 `src/dex-baseline/{classes,classes2}.dex`（`ffd82303…` / `c1504c10…`），
`.operit/sm/` 已随之删除。重新生成它们需要 smali 工具（`.operit/smali/*.jar`，baksmali/smali/dexlib2）——
纯为改 JS 出包时**不需要**动它们，直接 `--dex …=src/dex-baseline/…` 原样带上即可。

## §6 推送（唯一通道）

本地 commit 与远端 `main` 是**两条互不相关的历史**（历史上一直用 Git Data API 推快照提交，SHA 天然不同，
`git merge-base` 无交叉）。因此：

- `git push` **永远**报 `fetch first`，别试；
- 唯一可用通道是 `tools/push_repo.py`（快照 + `--prune`）：

```bash
GH_TOKEN=$(gh auth token --user xhjoyb) python3 tools/push_repo.py \
  --owner xhjoyb --repo coopanion-re --branch main --dir . --prune --workers 4 \
  --message 'P9: 出包链工具化 + 清理 197 M'
```

- 默认凭据是 `zqf1314`（对该仓库无权限，403），所以必须显式 `GH_TOKEN=$(gh auth token --user xhjoyb)`；
- `--prune` 会删远端多余文件（上次清了 156 个），**别在不确认清单的情况下乱用**；
- 打 tag 用 GitHub API：`POST /repos/xhjoyb/coopanion-re/git/refs`，`{"ref":"refs/tags/<tag>","sha":"<commit>"}`。

## §7 装机器

```bash
adb push <signed.apk> /data/local/tmp/ ; pm install -r /data/local/tmp/<signed.apk>
```

- 签名证书与 pet3 相同 ⇒ **直接覆盖安装，不丢数据**（`firstInstallTime` 保留、`lastUpdateTime` 更新）；
- 换证书（如 MT 测试证书）就必须先 `pm uninstall`，会丢 `shared_prefs`；
- 装完看四件事：① App 起得来；② 三个端口 LISTEN（`7797` 桌宠页 / `17788` 控制台 / `17899` 感知桥）；
  ③ `/proc/<node>/cwd/app/coop-stage/vendor/pet/web/` 里文件字节数对得上新包；④ `logcat` 无 `Uncaught`/`SyntaxError`。
- 桌宠不出现的已知坑：`shared_prefs/coopanion.xml` 的 `pet_window_wanted=false`（引导弹窗的「召唤桌宠」按钮
  其实是开关，点一次等于收回），需在 App 内手动点一次，详见 `BASELINE.md` P8「排障留档」。
